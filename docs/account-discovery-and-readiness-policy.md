# Account discovery and desktop readiness

Asana workspace discovery uses only `https://app.asana.com/api/1.0/workspaces`. Basecamp account discovery uses only `https://launchpad.37signals.com/authorization.json`. Both disable Axios redirects and proxy discovery while retaining TLS verification, headers, compact response mapping and existing authorized-account filtering. Optional root slash/default TLS-port canonicalization is supported; alternative authorities, API prefixes, userinfo, custom ports, query strings and fragments fail before HTTP. These source changes do not alter installed provider apps, OAuth grants or credentials.

The desktop listener retains its configurable local TCP port and defaults to 3197. Ports must be decimal integers from 1 to 65535. Readiness now passes Node HTTP options with the literal hostname `127.0.0.1`, numeric port and literal `/health` path instead of interpolating environment input into a URL. Existing retries, socket timeouts, cancellation and response handling remain unchanged. No redirect-following behavior is introduced. Original hosted cases exercise real loopback readiness and shutdown sockets separately from the added transport checks; no project code executes locally during preparation.

References reviewed 27 October 2026: [Asana workspaces](https://developers.asana.com/reference/getworkspaces), [Basecamp authentication and authorization discovery](https://github.com/basecamp/api/blob/master/sections/authentication.md), [Node HTTP options](https://nodejs.org/api/http.html#httpgetoptions-callback). These protections do not establish complete current-runtime/SDK, live-provider or deployment/data acceptance.
